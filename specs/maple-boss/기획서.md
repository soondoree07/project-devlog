## 1. 한 줄 요약
친구들이 메이플스토리 주간 · 월간 보스를 잡은 기록과 수익(결정석 + 드랍템)을 같이 남기고, 유저별 수익 순위와 월별 전리품을 보는 사이트.

## 2. 기술 스택
- Vanilla HTML + ES Module, 빌드 없음. Vercel 정적 배포(`git push` 자동, `vercel.json` 으로 js·css no-store).
- Supabase: Postgres + RLS(공유 정책) + Realtime. supabase-js v2(esm.sh). 공개 publishable 키만 코드에 둔다.
- 사이트 비밀번호: `site_settings.pw_hash`(sha256) + `verify_site_pw` RPC. 통과 여부는 브라우저 localStorage.

## 3. 핵심 기능 (v1.0)

### 3.1 유저 · 캐릭터 (`#/manage` 유저 관리)
- 유저 7명(잉짱 · 곰범 · 밈두 · 쭈히 · 몌린 · 혁쥬 · 기타), 유저마다 캐릭터(닉네임 + 직업) 여러 개.
- "기타" = 외부 인원 자리. 캐릭터 c-ext1~5 를 자리표로 쓰고, 화면에서는 "기타 − n +" 인원 수로만 고른다. 수익 순위에서 빠지고 삭제 버튼이 없다.

### 3.2 기록 수정 (기록 창)
- **2026-10-05부터 새 기록은 스케줄러 자동 기록으로만 들어온다.** 직접 추가 버튼(헤더 · 보스 기록 칸 · 빈 화면 · 카드의 "+ 이 파티로 보스 추가")은 모두 뺐고, 창은 기록 1건 수정 전용이다.
- 넓은 2단 창: 왼쪽 날짜 · 참여 캐릭터, 오른쪽 보스 칸.
- 보스 칸 = 보스(위쪽 11개 지정 순서 → 나머지 결정석 순, "보스 선택"부터) · 난이도 · 결정석 안내 · 그 보스 드랍템 버튼(눌러서 여러 개 담기) + 직접 입력.
- 드랍템 한 줄 = 이름 · 가격(억, 글자 칸) · 분배/독식 · 가져간 사람(독식일 때, 외부는 "기타").
- 수정은 기록 1건만(보스 칸 하나). 보스 · 난이도를 그대로 두면 처음 저장한 결정석 유지. 지운 캐릭터가 있던 기록도 인원 n 유지.

### 3.3 메인 (`#/`)
- **수익 순위**: 이번 주(목요일 0시 초기화) / 이번 달 / 전체, 유저별 = 캐릭터 몫 합.
- **N월 전리품**: 이번 달 드랍템 최신순(날짜 · 아이템 · 보스 · 누가 · 가격) + "전체 보기" 창(달마다 합계 · 목록). 줄을 누르면 그 드랍템을 먹은 기록 카드가 창으로 열려 수정 · 삭제.
- **보스 기록 카드**: 같은 주 · 같은 파티 기록을 한 장으로. 2열, 열마다 위에서 아래로 이어 붙임(좁은 화면은 한 열). 카드 머리는 혼자면 합계, 파티면 파티원마다 번 돈(외부 인원은 "기타 1인당"). 보스 줄마다 결정석(드랍템이 있을 때만) · 수익 · 드랍템("30억 1인당 10억 분배" / "9억 기타 독식") · 수정 · 삭제.
- 헤더: 다크 모드 전환 · 채널 룰렛(창) · 유저 관리 · **스케줄러에서 가져오기**(바로 가져오기 + 기록 다시 불러오기, 사이트를 열 때도 10분에 한 번 자동). 맨 아래 "과거 기록 보기".

### 3.4 과거 기록 (`#/archive`)
- 개편 전 옛 파티 밈곰잉(91회) · 쭈진(2회)을 달별로 정리한 읽기 전용 페이지.
- 파티 탭 → 파티 전체 파티원별 수익 → 달마다 누가 얼마 · 잡은 보스 · 드랍템(누가 · 얼마).
- `data/archive-2026.json` 고정 파일. 옛 가격표(git e3f8881)로 옛 계산 규칙 그대로 계산(`scripts/build-archive.mjs`).

## 4. 데이터 모델 (Supabase, `sql/v2-schema.sql`)
```
users(id, name, sort_order, is_external)
characters(id, user_id → users cascade, name, job, sort_order)
runs(id, date, boss, difficulty, crystal numeric, character_ids jsonb, loot jsonb, created_at)
  loot: [{ name, price, mode: 'split' | 'solo', takerCharacterId? }]
site_settings(id = 1, pw_hash)        -- 클라이언트는 읽지 못함, verify_site_pw RPC 로만 검사
party_presets(...)                    -- 만들었지만 화면에서 쓰지 않음
옛 테이블 parties / boss_runs / reservations / boss_settings -- DB에 남아 있으나 사이트는 읽지 않음
```

## 5. 계산 규칙 (`js/v2/calc.js`)
- 캐릭터 몫: 결정석 ÷ n + 분배 드랍템 ÷ n + 자기가 독식한 드랍템 전액 (n = 참여 캐릭터 수, 외부 포함).
- 유저 수익 = 그 유저 캐릭터 몫의 합. 외부 유저 제외.
- 금액 표기 `formatEok`: 0.1억 이상 소수 1자리, 그 아래 2자리, 0 은 "0억".

## 6. 결정석 가격표 (2026-10-01 이후, 나무위키 "현재 가격" 기준, #.#억 · 100만 단위 버림)
- 단일 출처 = `js/data.js` `BOSSES[].difficulties[].crystal`. 0.1억 미만 보스는 소수 2자리.
- 신규 보스 벨로나(이지 3.9 · 노멀 8.2 · 하드 29.5). 일간 보스(시그너스 · 핑크빈 · 힐라)는 숨김. 일간 보스 아카이럼은 기록한다(결정석 0억, 노멀 드랍 도미네이터 펜던트, 스케줄러 목록 · 자동 기록 포함, 자동 기록 기간 = 그날 · 파티는 어제 기록을 따라감).
- 드랍템 그룹: 유니크 · 해머 · 에픽 · 퍼플코어 · 소울 에테르(1~4단계, 퍼플코어 바로 아래) · 기본. 리3·컨3 은 목록에서 뺐다.
- 명칭: 연마석 = 생명의 연마석, 신마석 = 신념의 연마석, 에테상자는 종류 구분 없음.

## 8. 개발 히스토리

### 2026-10-05 — 기록은 스케줄러에서만
- 스케줄러가 자동으로 기록하므로 직접 기록 기능을 뺐다(사용자 결정): 헤더 · 보스 기록 칸 · 빈 화면의 `+ 기록 추가`, 카드의 `+ 이 파티로 보스 추가`.
- 헤더 새로고침과 보스 기록 칸의 가져오기 버튼을 헤더 "스케줄러에서 가져오기" 하나로 합침. 수정 · 삭제는 그대로, 기록 창은 수정 전용(`317f817`).
- 확인 당시 스케줄러 연결 4/6명(잉짱 · 몌린 · 밈두 · 곰범). 쭈히 · 혁쥬는 미연결 — 쭈히 기록 12건은 전부 직접 넣은 것이라, 쭈히 혼자 · 외부 인원과 잡은 보스는 연결해야 기록된다.

### 2026-10-04 — 전리품에서 기록 카드 열기 · 헤더 새로고침
- 이번 달 전리품 · 전체 보기의 줄을 누르면 그 기록 카드(같은 주 · 같은 파티)가 창으로 열린다. 카드 버튼은 창을 닫고 원래 동작(`97a4c02`).
- 드랍템 기본값은 파티면 분배, 1명이면 독식 고정 그대로 유지(사용자 확인).
- 헤더 새로고침: 스케줄러 바로 가져오기(10분 제한 없음) + 기록 다시 불러오기. 보스 기록 칸의 "스케줄러에서 가져오기"는 그대로 둠(`1ba38dc`).
- 본인 기록 카드 네온 테두리는 로그인이 없어 보는 사람을 알 수 없어서 하지 않기로 함(기기마다 '나' 고르기 방식 제안 → 사용자 거절).

### 2026-10-03 — 아카이럼 · 기록 카드 2열 · 파티원별 수익
- **아카이럼(일간):** 보스 목록에 추가(이지 · 노멀, 결정석 0억, 노멀 드랍 도미네이터 펜던트 — 사용자 결정). 서버가 일간 보스 중 아카이럼만 통과시켜 기록 창 스케줄러 묶음 · 유저 캐릭터 창에 나오고, 처치하면 매일 자동 기록(기간 = 그날, 파티는 어제 같은 보스 기록을 따라감). 나머지 일간 보스는 계속 버림.
- **기록 카드 2열:** 줄 맞춤(윗줄 기준) 대신 열마다 위에서 아래로 이어 붙임. 최신 카드부터 더 짧은 열에 넣고, 좁은 화면은 한 열 원래 순서.
- **파티원별 수익:** 파티 카드 머리의 파티 합계 대신 파티원마다 번 돈. 혼자 카드는 합계 그대로 (`16c7711`).

### 2026-10-01 — 넥슨 오픈 API 연결 1단계
- **조사:** 스케줄러 API(`/scheduler/character-state`, 본인 계정 전용 — 친구마다 각자 키 필요, 14일 전까지)로 캐릭터별 보스 목록 가능. 장비 · 스탯은 공개 API. 결정석 가격은 API에 없어 `js/data.js` 수동 유지.
- **장비 점수 방식:** 환산주스탯과 같은 원리 — 장비를 뺐을 때 그 캐릭터가 약해지는 만큼을 주스탯으로 환산, 주스탯 10 = 1점. 환산주스탯 숫자를 가져오지 않고 직접 계산. 제논 · 데몬어벤져는 처음엔 제외.
- **로드맵:** 1 연결 기반 → 2 장비 점수 · 스펙 랭킹(`#/spec`, 캐릭터별, 외부 인원 제외, 펫장비 · 캐시템 제외) → 3 스케줄러 보스 목록(없는 보스는 숨기지 않고 접기, 친구 키는 Supabase `nexon_keys` 에 서버만 읽게).
- **1단계 구현:** Vercel 서버 함수 `api/nexon.js`(키는 환경변수 `NEXON_API_KEY`, 허용 조회만, 10분 캐시, localhost 만 CORS 허용) + 유저 관리 "넥슨 확인" 버튼(`js/v2/nexon.js`, `nexon-check.js`). 키 등록 후 우리 캐릭터 12개 전부 조회 성공(없는 닉네임은 넥슨이 OPENAPI00004 로 준다).

## 8.1 장비 점수 (보류 — 2026-10-01 결정 사항)
- **원리:** 그 장비를 뺐을 때 캐릭터가 약해지는 만큼을 주스탯으로 환산, 주스탯 10 = 1점. 캐릭터 점수 = 장비 점수 합. 환산주스탯 숫자는 가져오지 않는다(부위별 기준값 비공개).
- **배율식:** (주스탯 x 4 + 부스탯) x 공/마 x (1 + 데미지 + 보공) x (1.35 + 크뎀) x (1 - 보스 방어율 x (1 - 방무)). 주스탯 = 최종 스탯이 가장 높은 것, INT 면 마력.
- **확정값(사용자):** 보스 방어율 **380%**, 크리티컬 **확률은 제외(모두 100%)**, **크뎀은 반드시 포함**, 세트 효과 제외, 최종뎀은 장비에 없어 제외(스킬 · 링크 · 헥사에서 옴), 제논 · 데몬어벤져 제외, 펫장비 · 캐시템 · "예비 특수 반지" 제외.
- **프리셋:** 장비 프리셋 1~3 중 **아이템 드롭률 · 메소 획득량 잠재가 없는 프리셋 = 보스용**, 그중 계산상 가장 센 것. 없으면 드롭 · 메소 줄이 가장 적은 것. 유니온 · 링크는 지금 적용 중인 것(다른 조합 전투력은 API 로 못 구함). 잉짱 예: 지금 2번(사냥, 드롭 · 메소 16줄), 3번이 보스용(0줄).
- **데이터:** `spec` 조회 = 최종 스탯 + 장비(프리셋 1~3 포함). `item_total_option` 은 잠재 제외 합계, 잠재 · 에디셔널 · 소울은 "STR +10%" 같은 문구라 정규식으로 읽는다. 주스탯% · 공% 의 장비 밖 몫은 장비 합계로 추정하고 나머지는 상수로 흡수.
- **화면(예정):** `#/spec` 캐릭터별 점수 순위(외부 인원 제외, "몇 번 프리셋 기준" 표시) → `#/spec/캐릭터` 부위별 점수와 근거. 출처 문구 표기.
