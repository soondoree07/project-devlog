## 4. 디자인 (2026-08-22 확정)

**무드 "자연 결".** 무드 8종을 실제 작품으로 렌더해 비교한 뒤 선택했다.

| 역할 | 값 |
|---|---|
| 바탕 / 면 | `#E8E0D3` / `#F2ECE1` |
| 글자 / 보조 | `#3A332A` / `#857B6B` |
| 선 / 진한 선 | `#D2C6B3` / `#B9A98F` |
| 강조 | `#9C6B4A` |
| 제목 글씨 | Gowun Batang (고운바탕) |
| 본문 글씨 | Noto Sans KR 300 (본고딕) |

**형태는 각지게 간다.** 사용자 지시로 둥근 모서리·그림자·기울임을 전부 걷어냈다.

- 곡률 0. 경계는 1px 선으로만 잡는다. `css/tokens.css`에 곡률·그림자 변수가 아예 없다
- 버튼 형태를 쓰지 않는다. 밑줄 달린 글자 + 화살표로 처리한다
- 배경에 거의 안 보이는 종이 결 텍스처 (SVG feTurbulence, opacity 0.32)
- 라이트 테마 단일. 다크 모드 없음

## 5. 주요 기능

### 5-1. 메인 페이지 (index.html)

- **히어로:** 「꿈결 물결 바람결」(2023)을 크게 건다. 작가명 + 태그라인만.
  작품 제목·재료·크기는 붙이지 않는다
- **작품 연보:** 12개 시기를 좌우 번갈아 배치. **"이 시기 보기" 버튼은 없고 연도 숫자 자체가 링크**다
  - 연도 아래에는 **그 시기 설명만** 온다. 작품 수는 표시하지 않는다
  - **설명 문체는 `-다` 체로 통일한다** (2026-08-25 확정). 작가 노트 문체이고,
    작가님이 보내주시는 원문이 이 결이다. 새 설명을 넣을 때도 여기에 맞춘다
  - 설명이 있는 9곳: 2025·2024·2023·2022·2021·2018–2020·2017·2011·2009 (101~204자)
  - 설명이 없는 3곳(2016·2014–2015·2012–2013)은 **빈 줄 다섯만큼(140px) 자리만 남긴다**
    ('비어있음' 글자는 2026-08-24에 없앴다)
  - 시기 대표 이미지는 `data.json`의 `thumbnail`에 **손으로 지정한 값**이다. 자동으로 뽑지 않는다
- **작가:** 소개글 + 이메일·인스타그램. **전화번호는 내지 않는다**
- **약력:** 6개 블록. 단체전 70줄은 기본으로 접혀 있다
  - 각 줄은 두 칸 이상 띄어쓰기로 연도/이름/장소를 나눠 3열 표로 그린다
- **문의:** 메일 주소와 인스타 아이디를 그대로 보여주고 **누르면 클립보드에 복사**한다.
  mailto 링크는 메일 프로그램이 없는 사람에게 아무 일도 일어나지 않아 폐기했다.
  복사가 막힌 환경에서는 글자를 자동으로 선택해 손으로 복사할 수 있게 한다

### 5-2. 시기 상세 (year.html)

- 비율 맞춤 격자 + **"순서대로 보기"**(첫 작품부터 라이트박스 슬라이드)
- 작품 제목은 **한 줄로 고정**한다. 데이터에 든 줄바꿈(`\n`)은 빈칸으로 바꾸고,
  칸보다 긴 제목은 말줄임하되 마우스를 올리면 전체가 뜬다
- 별도 페이지라 주소 공유·뒤로가기가 정상 동작한다

### 5-3. 라이트박스

- 좌우 이동, ESC 닫기, 키보드 화살표, 모바일 스와이프
- 누른 썸네일 자리에서 자라나듯 열린다 (Web Animations API)
- 열려 있는 동안 초점을 안에 묶어 둔다 (포커스 트랩)
- 원본 이미지를 쓴다 (격자는 썸네일)

### 5-4. 모션

- 스크롤 등장(순서대로 조금씩 늦게), 호버 시 작품 살짝 확대
- `prefers-reduced-motion`을 켠 사용자에게는 전부 정지

## ★ 작품 이미지 비율 — 레이아웃의 전제

**세로형이 거의 없다. 가로형 56점 / 정사각 62점 / 세로형 4점.**
「구름에 기대 꿈을 그리다」는 **8.28 : 1 파노라마**(100×45cm 15점 세트)이고 5:1, 4:1도 여럿이다.

→ **핀터레스트식 세로 Masonry를 쓰면 안 된다.** 비율에 따라 칸 수를 바꾼다
   (`js/data.js`의 `spanOf`: 3:1 이상 한 줄 통째 8점 / 1.55 이상 2칸 24점 / 나머지 1칸 90점).
   좁은 화면에서 파노라마는 높이를 지키고 가로로 민다.

```json
{
  "artist": {
    "name": "배정혜",
    "tagline": "한 줄 소개",
    "bio": "소개글",
    "email": "jh0329ms@naver.com",
    "instagram": "https://www.instagram.com/artist_jbae/"
  },
  "years": [
    {
      "year": 2026,
      "description": "연도 설명",
      "thumbnail": "images/2026/thumb.jpg",
      "works": [
        {
          "title": "작품 제목",
          "material": "Mixed Media",
          "size": "114×162cm",
          "description": "작품 설명",
          "image": "images/2026/파일명.jpg",
          "solo": true
        }
      ]
    }
  ]
}
```

**2026-08-22 추가 필드** (`tools/build_image_meta.py`가 자동으로 넣는다):

| 필드 | 설명 |
|---|---|
| `w` / `h` | 이미지 실제 픽셀 크기. 격자 칸 수 계산과 로딩 중 화면 밀림 방지에 쓴다 |
| `thumb` | 격자용 WebP 썸네일 경로 (`images/thumb/…`) |

**작품 필드:**
| 필드 | 설명 |
|---|---|
| `title` | 작품 제목 |
| `material` | 재료 (예: Mixed Media, Oil on Canvas) |
| `size` | 크기 (세로×가로cm) |
| `description` | 작품 설명 |
| `image` | 이미지 경로 (images/연도/파일명.jpg) |
| `solo` | 단독 배치 여부 (true: 1열 전체, 없으면 그룹 배치) |

## 8. 이미지 처리 원칙

- 흰색 테두리·캡션 자동 크롭 (Python 스크립트 처리)
- 이미지 압축 후 업로드
- `images_backup/` 폴더에 원본 백업 보관
- 크기(cm) 기재 시 세로×가로 순서 확인 필수 (오기재 이력 있음 — 픽셀 비율로 자동 검증)
- 작품 제목 대소문자: 영문 제목은 모든 단어 첫 글자 대문자 (Title Case)
- 줄바꿈 표현 필요 시 `\n` 사용 (렌더링 지원)
- **작품을 추가하면 반드시 `python3 tools/build_image_meta.py` 를 실행한다.**
  이미지 크기를 재서 `data.json`에 `w`/`h`/`thumb`를 넣고 썸네일을 만든다.
  빼먹으면 격자 배치가 틀어지고 로딩 중 화면이 밀린다

## 7-2. QR 코드 (2026-08-24 확정)

`docs/qr/` — 기본 / 흑백 / 나비 없는 안전판, 각각 SVG + PNG.

- 버전 3, **29×29 모듈**, 오류 정정 **H**. 최소 인쇄 크기 2cm
- 가운데 나비 판은 **정확히 11×11 모듈**. 가려지는 면적 14.4% (H 허용 30%)
- **판 크기를 비율(%)로 잡지 말 것.** 소수 모듈이 되면 격자 중간이 잘려
  가장자리에 반쪽 칸과 실선 자국이 남는다. 홀수 모듈 수로 잡는다
- 사용자가 실제 폰으로 스캔해 연결 확인 완료

## 8-2. 모바일 반응형 (2026-08-22 검증)

320 / 360 / 390 / 414 / 768px 다섯 폭 실제 렌더 측정 — 전부 통과.

- 가로 넘침 0건, 갤러리 1열 전환, 본문 16px
- 파노라마는 높이 190px 유지 + 가로 스크롤
- 라이트박스 이미지가 설명을 덮지 않고 화면 밖으로 넘치지 않음
- **터치 크기 44px 미만 0건.** 작던 링크는 여백 대신 가상 요소로 눌리는 범위만 넓혔다
  (여백을 주면 밑줄이 글자에서 떨어져 디자인이 흐트러진다)
